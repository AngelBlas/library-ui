# Design Guidelines

## Purpose

Define the visual standards for the Angular application using Angular Material.

> Status: MediApp currently relies almost entirely on Angular Material's default Material 3 theme (`src/material-theme.scss`). Very little custom design has been layered on top, and a couple of components (delete/cancel buttons) hardcode colors outside the theme. Sections below are filled with what is actually implemented today; gaps are marked **TODO** with a recommendation.

---

# Theme

* **Theme Type**: Light only. `body { color-scheme: light; }` is hardcoded in `src/styles.css`. No dark theme or `light dark` system-preference support is wired up yet.
* **Engine**: Angular Material 3 theming via the `mat.theme()` Sass mixin (`src/material-theme.scss`), applied at the `html` level. Styles are generated as CSS custom properties (`--mat-sys-*`) rather than a static palette file.
* **Primary Color**: `mat.$azure-palette` (Material 3 Azure)
* **Secondary Color**: Not explicitly set — Material 3 auto-derives a secondary tonal palette from the primary (Azure). **TODO**: set explicitly if brand requires a specific secondary.
* **Tertiary Color**: `mat.$blue-palette`
* **Surface Colors**: Material 3 system tokens (`--mat-sys-surface`, `--mat-sys-on-surface`, etc.), consumed directly in `body` for background/text. No custom surface overrides.
* **Error Color**: Not themed — components needing an "error/destructive" look (e.g. the Delete/Cancel buttons) hardcode `background-color: red` via a global `.cancel-button` class in `src/styles.css` instead of using `--mat-sys-error`. **TODO**: replace with the Material system error color for consistency and theming support.
* **Density**: `0` (default Material density, no compact mode).

# Color Palette

## Brand Colors

* **Primary**: Azure (`mat.$azure-palette`) — resolved at build time to `--mat-sys-primary` / `--mat-sys-on-primary`.
* **Secondary**: Auto-derived Material 3 tonal palette (not explicitly branded). **TODO**.
* **Accent**: Angular Material 3 no longer uses a distinct "accent" role; use **Tertiary** (`mat.$blue-palette`, `--mat-sys-tertiary`) instead.

## Semantic Colors

* **Success**: Not defined. **TODO** — no success state exists anywhere in the app (e.g. save confirmations). Recommend adding a snackbar using `--mat-sys-tertiary` or a custom success token.
* **Warning**: Not defined. **TODO**.
* **Error**: Currently hardcoded `red` (`.cancel-button` in `src/styles.css`), used for both "Cancel" and "Delete" actions. Should be migrated to `var(--mat-sys-error)` / `var(--mat-sys-on-error)` so it participates in the Material 3 theme instead of a fixed hex value. Form validation messages (`small.invalid`) also hardcode `color: red` (see `exam-edit.component.css`) — same fix applies.
* **Info**: Not defined. **TODO**.

## Neutral Colors

* **Background**: `var(--mat-sys-surface)` (set on `body`).
* **Surface**: Material 3 system surface tokens; `.mat-shadow-2` utility class used to elevate the exam table container (`exam.component.html`).
* **Border**: No custom border tokens; relies on Material component defaults (`mat-divider` for sidenav sections).
* **Text Primary**: `var(--mat-sys-on-surface)` (set on `body`).
* **Text Secondary**: Not explicitly defined; relies on Material component-level tokens (e.g. table header vs. cell contrast) where used.

# Typography

* **Font Family**: Roboto, loaded from Google Fonts in `src/index.html` (`family=Roboto:wght@300;400;500`) and declared as the Material typography config (`typography: Roboto` in `material-theme.scss`).
* **Headings**: No custom heading styles defined in the app; none of the current pages (`exam`, `exam-edit`, `specialty`, `layout`) use `<h1>`–`<h6>`. Relies on Material typography scale (`--mat-sys-headline-*`, `--mat-sys-title-*`) if/when introduced.
* **Body Text**: `var(--mat-sys-body-medium)` set globally on `body` in `src/styles.css`.
* **Labels**: Field labels use `mat-label` inside `mat-form-field` (e.g. `exam-edit.component.html`), styled by Material's default label typography. Table filter field is manually sized to `14px` (`exam.component.css`), slightly deviating from the system type scale.
* **Buttons**: Default Material button typography (`mat-flat-button`, `mat-fab`, `mat-icon-button`), no overrides.

# Spacing & Layout

* **Spacing Scale**: Not defined — no custom spacing tokens/utility classes exist. Layout relies on flexbox (`display: flex; flex-direction: column`) in container classes (`.example-container` in both `layout` and `exam-edit` components) with default browser/Material spacing. **TODO**: introduce a spacing scale (e.g. 4/8px base) if the app grows.
* **Border Radius**: Not customized; uses Angular Material 3 defaults (shape tokens) as generated by `mat.theme()`.
* **Elevation (Shadows)**: `.mat-shadow-2` utility applied to the exam data table wrapper for a subtle raised effect; otherwise default Material elevation on components like `mat-toolbar`, `mat-menu`, and `mat-fab`.
* **Responsive Breakpoints**: **TODO** — none defined. The sidenav is hardcoded to `mode="side"` at a fixed `width: 250px` (`layout.component.html`) with no responsive collapse for mobile (e.g. `mode="over"` on small screens). This is a gap worth addressing if mobile support is a goal.

# Angular Material Components

Component usage as actually implemented in the codebase:

* **Buttons**: `mat-icon-button` (toolbar menu/overflow), `mat-flat-button` (form submit/cancel, table row actions), `mat-fab` (add new exam, floated via inline `style="float:right"` in `exam.component.html` — **TODO**: move to CSS class instead of inline style).
* **Form Fields**: `mat-form-field` + `mat-label` + `matInput`, used with Angular's new **Signal Forms** API (`[formField]`, `[formRoot]`, `examForm.$form`) in `exam-edit.component.html` — notable since this is a cutting-edge/experimental Angular API, not the legacy `FormGroup`/`FormControl` reactive forms pattern.
* **Cards**: Not currently used anywhere in the app. **TODO** if card-based layouts are needed.
* **Dialogs**: Not currently used — e.g. exam deletion has no confirmation dialog (`delete(row.idExam)` fires directly). **TODO**: consider `MatDialog` for destructive confirmations.
* **Tables**: `mat-table` with `matSort`, `mat-paginator` (page sizes `[3, 10, 25, 100]`), and a "no data" row via `*matNoDataRow`, seen in `exam.component.html`. This is the primary data-display pattern for list views.
* **Navigation**: `mat-sidenav` / `mat-sidenav-container` (fixed `side` mode) + `mat-toolbar` + `mat-menu` (overflow "more" menu with account/logout) + `RouterLinkActive` for active-route highlighting (custom `.active` class, not a Material token).
* **Snackbars**: Not used yet. **TODO** — no user feedback pattern exists for success/error toasts after CRUD operations.
* **Progress Indicators**: Not used yet. **TODO** — no loading spinner/bar exists for async operations (HTTP calls via `provideHttpClient()` have no visible loading state).

# Component States

* **Default**: Standard Material component appearance, no overrides.
* **Hover**: Default Material ripple/hover states; no custom hover styling.
* **Focus**: Sidenav nav buttons have a custom (and arguably unwanted) focus override in `layout.component.css` — `.myButton:focus` strips the focus box-shadow/background/tap-highlight, which reduces focus visibility and is a potential accessibility regression. **TODO**: reconsider — this fights against visible focus indication.
* **Active**: Active route in the sidenav is marked via `.active { background-color: #dcdcdcc1; }` — a hardcoded gray rather than a theme token. **TODO**: use a Material system color (e.g. `--mat-sys-secondary-container`) for theme consistency.
* **Disabled**: Submit button disabled state driven by form validity (`[disabled]="examForm.isInvalid()"` in `exam-edit.component.html`), using default Material disabled styling.
* **Loading**: Not implemented anywhere. **TODO**.
* **Error**: Inline validation messages (`<small class="invalid">`) shown conditionally based on Signal Forms error state (`required`, `minLength`) in `exam-edit.component.html`; styled with hardcoded `color: red` rather than the Material error token. **TODO**: align with `--mat-sys-error`.

# Accessibility

* **Color Contrast**: Not audited. Material 3 default tokens should pass WCAG AA out of the box, but hardcoded colors (`red` cancel/delete buttons, `#dcdcdcc1` active nav state) haven't been checked against contrast requirements. **TODO**: run a contrast audit once semantic colors are formalized.
* **Keyboard Navigation**: Relies on native Material component behavior (buttons, menu, sidenav); no custom keyboard handling. The `.myButton:focus` override in `layout.component.css` (see Component States) actively suppresses visible focus styling, which works against keyboard navigability. **TODO**: fix.
* **Focus Indicators**: Weakened by the custom focus override noted above. **TODO**: restore or replace with a deliberate, visible focus style.
* **Screen Reader Support**: Minimal — only one `aria-label` in the app, on `mat-paginator` (`aria-label="Select page of users"` in `exam.component.html`). Icon-only buttons (toolbar menu, overflow menu, edit/delete actions use text+icon so are OK) — the sidenav toggle and overflow-menu trigger `mat-icon-button`s have no `aria-label`. **TODO**: add `aria-label`s to icon-only buttons.

# Design Principles

* **Consistency**: Partial — most UI leans on Material defaults, but a few hand-rolled colors (red buttons, gray active state) break from the token-driven theme and should be reconciled.
* **Reusability**: Low so far — styling is duplicated per component (`.example-container` pattern repeated in `layout` and `exam-edit` with the same name but different rules); no shared style/utility file beyond `src/styles.css`. **TODO**: consider a shared class naming convention as more feature pages (`specialty`, future `medic`, `patient`, `report`, `consult-wizard`) are built out.
* **Accessibility**: Baseline Material accessibility, undermined by the custom focus-suppression rule; needs attention as noted above.
* **Responsive Design**: Not yet addressed — fixed-width side nav, no breakpoints. **TODO** before mobile/tablet use is expected.
* **Material Design Compliance**: Largely compliant since the app uses stock Material 3 components and theming; the main deviations are the hardcoded destructive-action color and active-nav-state color, which should be migrated to theme tokens for full compliance.
